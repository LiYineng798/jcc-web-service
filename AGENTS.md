# Repository Guidelines

The account-center `#accountApp` uses the shared `account-grid` layout with 20px between its dashboard/history/reports/mine sections (16px on screens up to 640px). Account subtitles have 8px separation, consecutive metadata rows have 6px, and history action buttons have 12px above them.

Avatars retain transparent backgrounds on every surface, including dark mode and editor previews. Regular lineup cards leave 12px between the code preview and its immediately following action row.

User avatars use the fixed striped-sphere SVG supplied in the local `yangshi` reference, copied into `static/avatar.js` with no external runtime dependency. Only a six-digit `users.avatar_color` is persisted; registration/admin creation randomly choose a system color, and SQLite legacy migration backfills missing colors without changing existing choices. `PUT /api/me/avatar` accepts exactly `{color: "#RRGGBB"}`, requires an active session and CSRF, updates only the current user, and invalidates the shared homepage cache revision. Keep this schema aligned with DB migration `0014_user_avatars.sql`, deployed before Web. Account payloads expose `avatar_color`; lineup payloads expose `owner_avatar_color` through existing joins. `static/avatar-editor.js` and `static/avatar.css` own the account-center editor, preset/custom color preview, cancel/save behavior, and responsive themes. The homepage account menu links to `/me#avatar`, guests have no header avatar, and regular cards, author profiles, and lineup details show the shared avatar. Do not accept uploads, arbitrary SVG, geometry, or external image URLs.

This is the Web service repository for the JCC workspace. Make Web/API/UI changes here and commit them in this repository.

The lineup simulator at `/tools/lineup-simulator` is a standalone dark tool workspace implemented by `templates/lineup_simulator.html` and `static/tools/lineup-simulator/{app.js,style.css}`. It reads every season dynamically from `static/season-data/catalog.json` plus each season's `champions.json`, `traits.json`, `items.json`, and `board_units.json`; do not add season-id branches or restore the legacy generated simulator data path. New season-specific behavior must be driven by shared schema capabilities such as `availability.type=unlock`, `recipe.component_ids`, and board-unit `placement_rules`. Board units are trait-created objects that stay out of the public library, do not contribute traits or cost, default to no equipment unless `can_equip=true`, and become placeable only up to the cap unlocked by current trait counts. Item-category tabs are also data-driven and only render when the current season contains at least one item in that category. The season-library importer generates version-isolated 96px WebP images for champion/skill/item/trait/board-unit icons and records them as `optimized_local_path`; simulator thumbnails must prefer those paths while hover-card splash art keeps the original large image. The simulator supports a container-responsive flat 7-by-4 hex board that must remain fully visible at every layout width, duplicate units with unique-per-champion trait contribution, three items per unit, recipe component totals, toggleable hover details, an icon-based grouped trait picker beside champion search that dims non-matches, formation import/export/share, wide-format DOM image export with an optional height-limited trait rail and optional transparent PNG background, undo/redo, and per-season local persistence. Composite activation text must never attach a rule to a source trait that references itself; in S18, 3 日蚀骑士 plus 3 月蚀骑士 displays the source counts as 3 and activates 日月双蚀 at 6. New formation exports use the fixed 321-character `JCC2-` binary code with season/codebook hashes and a checksum; legacy Base64 JSON codes remain import-only. Both wide image and fixed 1200-by-1600 portrait-poster exports close their native settings dialog before showing the staged animated progress overlay, so the browser top layer cannot cover the animation. The poster title is entered only in the poster dialog, the background is selected from unique deployed non-board-unit champions (defaulting to the highest-cost champion and then board order), and the selected landscape splash is rendered twice so a softened fill covers the portrait canvas while a sharp, aspect-preserving foreground copy remains fully visible. The board keeps names and items, active traits are compacted to nine rows plus overflow, and the quiet footer uses the site favicon without the site domain; it never changes formation payloads or replaces the existing wide export. Poster titles use the bundled Source Han Serif SC VF WOFF2 subset under `static/tools/lineup-simulator/fonts/`, whose SIL OFL license must remain beside it. The board footer's item-selection hint is hidden while no library item is selected and must not imply that equipped items are absent. Trait summaries are ordered unique, prismatic, gold, silver, bronze, then inactive; breakpoint `style=unique` is the canonical unique-trait signal. Keep champion portraits and trait tier frames as real image elements so DOM image export can embed them reliably.

Simulator board-unit rules now supersede the earlier blanket statement that these objects never contribute traits. Pre-combat objects are dynamically discovered from official trait text, explicit placeable/bench champion skill text, and snapshot fields. `trait_ids` are unlock/filter associations, while `contribution_trait_ids` alone add trait counts (for example, Tibbers is unlocked by Dark Child and contributes Mage). `placement_rules` can use either `trait_id` or `champion_id`. Record `extensions.discovery_sources`, do not add season-id frontend branches, and do not use unreleased seasons to validate live rules. Regular champions can also declare those effects in their official trait description: the simulator parses “占用 N 个弈子/队伍栏位” as population weight and “提供 +N【特质】” as that champion's trait contribution. The formation payload continues to persist only placement IDs, so existing local formations and fixed `JCC2-` codes pick up corrected weights when reloaded.

The sibling `..\jcc-db-service` repository owns PostgreSQL migrations, database import/export tooling, backups, restores, and database deployment runbooks. Do not edit database-service files from this repository. If a Web change depends on new database schema or seed data, make and deploy the DB-service change first, then commit the Web change here.

The parent `..\` directory is only a local coordination workspace and may also contain delivery artifacts such as `.sqlite3`, `.tar`, `.bundle`, or worktree files. Do not use the parent repository for normal feature commits.

For Web behavior changes, add or update focused tests under `tests/` and run at least the affected test subset with `python -m pytest -q`.

Public pages should pass explicit SEO metadata through `seo.py` and `templates/seo_head.html`. Keep login, account, admin, editor, API, hidden, and draft surfaces noindex or out of `sitemap.xml`; public detail pages should render useful first-load HTML before JavaScript hydration.

Season reference data is served from the season library under `static/season-data/` (see `docs/season-library.md`). Champion grids use generated WebP thumbnails, while detail pages and trait-member hover cards use full `splash` art. Items without independent source art must keep a local fallback with provenance under `extensions.image_fallback_*`. Import-time rich-text normalization stores safe `description_tokens`/`effect_tokens` for recognized stat markers while preserving the source strings. `static/season-data/catalog.json` drives the homepage `资料库` menu, the mobile resource dialog, the sitemap, and the `/tools/seasons/<season_id>` pages, so adding a season to the archive plus one import command publishes it everywhere.

The admin daily-report feature snapshots one calendar day's activity into `daily_admin_reports` (one row per `report_date`, headline totals denormalized, full report in `payload_json`). `daily_report_service.py` owns aggregation and persistence: summary UV/PV and new/returning visitors (plus 3-day/7-day return windows), registrations, successful logins, successful copies (regular + live comp from `copy_action_events`), new lineups, guestbook, reports, likes, favorites, 24-hour UV/PV/copy series for the heatmap, top pages, top copied codes, a season/version copy rank (`season_copy_rank`), a top visitor-IP panel (`top_visitor_ips`, admin-only), and deltas versus the most recent earlier report. `daily_report_worker.py` starts one daemon thread per Flask process and auto-generates yesterday's report shortly after midnight (insert-or-ignore makes concurrent workers idempotent); tests disable it via `TESTING`. Admin routes are `GET /api/admin/daily-reports`, `GET /api/admin/daily-reports/<date>`, and `POST /api/admin/daily-reports/<date>/generate` (CSRF-protected, writes an audit log). The admin live-comps workspace can create new live-comp seasons through `POST /api/admin/live-comps/seasons` (dialog next to 赛季管理; slug id + name + status, hidden-by-default recommended until data is uploaded) and can refresh the public updated_at of the selected season via `POST /api/admin/live-comps/seasons/<season_id>/touch-updated-at`, which bumps the season data file's mtime (per season; errors if the season has no data file yet).

管理员实时阵容工作区还提供 `数据上传`：管理员通过 Session + CSRF 上传 UTF-8 JSON 到 `POST /api/admin/live-comps/uploads/preview`，服务端校验并返回新增、移除、修改、阵容码变化、缺码和历史复制影响；确认后调用 `POST /api/admin/live-comps/uploads/<job_id>/start`，由进程内后台 worker 异步缓存图片并原子替换赛季文件。任务进度通过 `GET /api/admin/live-comps/uploads/<job_id>` 查询，旧数据在 `instance/live-comps-backups/<season_id>/<timestamp>.json` 生成版本化备份，失败时保留线上旧文件；任务状态和审计动作写入 `live_comp_upload_jobs` 与 `audit_logs`。SQLite schema/backfill 和 PostgreSQL migration `0009_live_comp_upload_jobs.sql` 必须保持一致。

审计日志的 `target_id` 仅用于数字数据库 ID；赛季 ID、日期、UUID 上传任务和复合标识必须写入 `audit_logs.target_key`（文本）。SQLite schema/backfill 和 PostgreSQL migration `0010_audit_target_key.sql` 必须保持一致。管理员审计列表同时显示 `target_key` 和旧的 `target_id`，避免字符串目标在 PostgreSQL 中写入 `BIGINT` 导致“业务已完成但接口返回失败”。

Simulator and reference-library seasons use the runtime policy file `instance/season-visibility.json`, managed through `/api/admin/season-display/simulator` and `/api/admin/season-display/library`. The admin workbench can reorder seasons and set `active`, `archived`, `hidden`, or `disabled`; simulator seasons also have one public default, with automatic fallback to the first public season if that default is hidden or disabled. Only active/archived seasons are returned by `/api/season-catalog`, hidden/disabled reference pages return 404, and shared season-data assets return 404 when the season is unavailable on both surfaces. Public live-comp cards may include a hidden `tftCode` plus optional `formationDetails` (`champion_id` or `source_champion_id`, `position`, `items` or raw `source_item_ids`, `star`); list responses strip the hidden code/details and `/api/live-comps/<id>/details` powers the optional board view. The detail board reuses the simulator's staggered honeycomb geometry and resolves equipment against library item and source IDs. The simulator places newly clicked/imported champions using attack-range zones (0/7/21 start with wraparound) and accepts standard TFT team codes when a generated season codebook is present.

Performance conventions (2-core/2GB host): production runs gunicorn via `deploy/gunicorn.conf.py` (2 gthread workers x 4 threads) behind nginx, which serves `/static/` directly with long cache lifetimes and gzip — keep `deploy/nginx.conf.example` and `deploy/jcc.service.example` in sync with the live configs. Site JS/CSS references in templates must go through the `static_v()` template global (auto mtime stamp) so cached assets refresh on deploy. Mutable `static/season-data/**/*.json` files must use `max-age=0, must-revalidate`; the simulator also appends one content-derived `season_data_stamp()` to the catalog and season JSON URLs, while season-data image URLs carry `?v=<version_id>`. PostgreSQL connections come from a small `psycopg_pool` in `db.py`. Page-view tracking only records logged-in users or guests that echoed the visitor cookie, and skips bot user agents; a genuine visitor's first page view is uncounted by design. Query caches in `lineup_cache.py` are bounded LRUs whose revision lives on the entry (score-style caches tolerate a 10s-stale revision in production). Event tables are pruned manually via `scripts/maintenance/prune_events.py` (dry-run by default, never scheduled automatically). Admin date filters use half-open `created_at >= ? AND < ?` ranges — never `LIKE 'day%'` or `substr()` — and new indexes must be added both to `db_schema.EXTRA_INDEX_STATEMENTS` (SQLite) and a `jcc-db-service` migration (PostgreSQL).

Production Git pulls run as root under a strict umask, so new tracked static files can arrive as owner-only. Every Web deployment must restore ownership to `jcc:jcc` and run `chmod -R a+rX /opt/jcc/jcc-web-service/static` before the Nginx/static-asset smoke checks; otherwise new CSS, JavaScript, images, or SVG stat icons can return 403 even while Flask health checks pass.

Released seasons may include `augments.json`, generated during Web import from Tencent's versioned official `hex.js`; every released season including S18 (official client season S19 / mode 18, live 18.18.1) generates augments, while a brand-new season with no DataJ observed-match sample yet keeps empty stage lists and `stage_data_unavailable`. This official augment fetch is allowed and supersedes the earlier archive-only wording, but DataTFT remains forbidden. The importer localizes original and versioned WebP icons, writes `augment-changes.json`, classifies categories through the documented site rule, and uses version-matched DataJ observed-match snapshots for per-augment 2-1/3-2/4-2 stages; unmatched entries must keep an empty stage list instead of inferring every stage. Season reference pages and the simulator use the same non-scrolling grouped augment filter pattern: tier, appearance stage, then category; omit “all” buttons and clear one group when its active option is clicked again. The simulator exposes champions and augments as peer library modes, persists up to six selected augments locally and in undo/redo history, and renders them in the portrait poster without changing the fixed JCC2 formation-code layout.
