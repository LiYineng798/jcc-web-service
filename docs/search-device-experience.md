# 搜索、设备分析与列表返回

## 当前边界与实现方案

首页以原生 JS 驱动，普通阵容、实时排行各自有赛季选择；普通阵容按名称 LIKE 匹配，收藏和个人阵容受账号权限保护。后台已有增长分析和日期日报。本功能在增长分析增加“搜索与设备”工作区，复用现有卡片、表格和浅深色主题。

1. 搜索分析记录普通阵容列表成功显示的搜索条件和实际结果数。搜索结果接口签发限时凭据，浏览器确认停留 700ms 后提交；结果数由服务端签名，统计提交不重复执行搜索。输入中的请求不直接计数；同一条件下翻页、复制后刷新、列表恢复不重复计数。切换关键词/赛季/排序产生新条件。收藏/个人视图、管理员、机器人、空关键词和失败请求不采集。
2. 访问和复制写入粗略设备标签。原记录不回填猜测，保持 unknown。后台显示搜索次数、人数、无结果次数/比例、按设备的访问和成功复制、前 20 热门/无结果关键词；关键词按赛季和排序分组。
3. 空状态分别解释搜索、SS、收藏、个人内容和实时数据，提供与场景对应的操作。网络失败显示重试并保留条件；过期响应不覆盖新筛选，也不参与统计。
4. 列表状态保存到当前历史条目和本标签页 sessionStorage，30 分钟有效；包含标签、两类赛季、关键词、页码、滚动位置、可见卡片及偏移。刷新/浏览器返回/详情返回入口恢复；普通首页新访问保留原默认实时视图。数据加载后按卡片定位，卡片消失时使用有边界的滚动位置。账号变化不读取上一账号状态，存储不可用时仍可正常使用。

## 统计口径

- 搜索统计的是首页普通阵容列表（all 视图），结果数按当时访客权限和筛选的实际可见结果计算；登录作者在该列表可能包含自己的隐藏阵容。只说明搜索有无匹配，不代表已采用/复制。
- 关键词最多 80 字符；统计时合并连续空白并 casefold，搜索匹配规则本身不变。
- 访客沿用账号或已有 visitor cookie；无稳定身份不记录。Cookie 不可用时不虚构人数。失败提交静默处理，不影响搜索。
- 搜索提交需要 CSRF、当前访客匹配的 10 分钟有效结果凭据和 32 位随机事件 ID；按访客+ID 唯一，IP 每 5 分钟最多 120 次新提交。统计接口仅管理员可读且 private/no-store。
- 设备分手机、平板、电脑、未知，仅保存分类，不保存原始 UA。iPad 桌面模式含 Mobile 的标识按平板识别；无法保证识别所有伪装 UA。
- 访问沿用“日+访客+页面类型”去重，同日跨设备可能只保留首次记录；跨设备人数有重叠。成功复制动作包含普通/实时、计分去重与未计分动作；复制人数独立去重，不能直接当作访问转化率。
- 日期范围最多 90 个自然日，包含今天、不允许未来日期。统计查询使用 created_at 半开范围与索引，不对日期列调用函数；榜单最多 20 项；非测试环境缓存 30 秒，刷新可重新查询。数据自启用后开始，旧日报不用重新生成。

## 数据与上线

Web SQLite schema/升级同步设备字段和 search_events；PostgreSQL 由 DB 仓库的 0017_search_device_analytics.sql 管理。新表加入 SQLite 导入顺序、identity 恢复和完整性检查。生产须先备份并应用 DB 0017，再更新 Web/worker。无需 React 构建，不更新生产环境配置。

## 体验路径

- 首页切换“最新”，输入阵容名或不存在的关键词，停留后查看提示与动作。
- 筛选赛季/关键词、进入第二页，滚动到卡片后点“查看”；使用浏览器返回或详情的“返回阵容库”验证状态和位置。刷新也保留状态。实时详情返回使用相同机制。
- 后台 → 增长分析 → 搜索与设备，选择近 7 天/30 天或自定义日期；普通用户搜索才会进入统计。
- 实时列表无数据、SS 无结果、收藏为空、个人内容为空均有专属提示。网络失败出现“重新加载”，不会写成无结果搜索。

测试入口：tests/test_experience.py；tests/serve_search_device_preview.py 与 tests/search_device_experience.browser.cjs。预览使用独立虚构数据和 loopback 端口，不注册到正式应用。

## 本次本地预览验收

预览首页为 http://127.0.0.1:5128 。测试账号为 previewadmin、previewuser，密码均为 Preview1234；仅供本机虚构数据库使用。快捷入口 /__preview__/login/admin 和 /__preview__/login/user 只存在于测试启动脚本。应用及数据库主仓库保持不变，两个服务分别在 codex/search-device-experience 分支提交，确认后再合并。

1. 在首页选择“最新”，S11 输入“九五”，切到第 2 页，滚动到某个阵容后点击“查看”。分别用详情中的返回入口、浏览器后退和返回后刷新，检查关键词、赛季、标签、页码和原卡片位置。实时阵容点棋盘详情再返回也应定位原卡片。
2. 输入“没有这样的阵容”，确认提示说明当前赛季和名称匹配范围；点“清除搜索”回到原赛季的完整列表。登录 previewuser 后分别打开“我的收藏”“我的”，检查提示及对应入口。选择 S17 的 SS、S18 实时列表可以查看另外两种空状态。
3. 切到预览管理员，后台“增长分析”→“搜索与设备”，查看四个概览指标、按设备数据、热门搜索和无结果关键词。可选近 7/30 天、无数据历史区间及最多 90 天自定义范围；超过 90 天会显示日期错误。手机使用设备卡片，桌面使用对比表格，沿用原有主题。
4. 要观察新增统计，使用未登录窗口或 previewuser 搜索并停留约 1 秒，然后管理员点击“刷新”。管理员自己的搜索不计入。翻页、详情返回和刷新恢复不会重复增加同一轮搜索。预览初始数据及浏览器验证产生的统计都是虚构数据。

设备分析帮助定位访问、复制和搜索无结果的差异，本次不采集加载耗时、真实 Web Vitals 或搜索后的复制归因，也不更改名称匹配算法。设备标签是粗略识别，历史未知数据保持未知。浏览器验证覆盖 Chromium/WebKit、390/1440 宽度和深浅主题，并包含禁用存储、迟到响应、账号切换和失败重试；桌面 WebKit 验证不代替真实手机验收。PostgreSQL 0017 尚需在正式更新时执行并核验，本次没有连接或修改线上服务。
