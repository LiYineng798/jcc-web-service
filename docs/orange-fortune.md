# 大橘大利时间卡片资料

此工具属于独立模式，不修改资料库赛季 ID、普通阵容分类或 PostgreSQL 结构。
页面 `/tools/orange-fortune` 使用随代码交付的资料和图片，运行时不依赖外部采集目录或 CDN。

## 来源与版本

- 当前资料由 `scripts/collect_orange_fortune.py` 从[官方版本目录](https://game.gtimg.cn/images/lol/act/jkzlk/js/config/versiondataconfig.js)选取分支后采集：`card.js` 是纯 JSON，顶层版本 `18.18.1`、`season=S400001`、`setId=16`，时间 `2026-10-28 10:49:42`，共 201 张。采集时间、ETag 与 Last-Modified 写入 `cards.json` 的 `provenance`。
- 分支按 `mode=16` 与 `season=S400001` 同时匹配；`mode=16` 还有普通英雄联盟传奇的其他 season，条目 `name` 也写“英雄联盟传奇”，`is_newest_version` 曾为 0 但资料仍在更新，三者都不能单独作为筛选依据。同一 season 出现多条时取 `version_start_time` 最新者，采集报告列出全部候选。
- 同目录 `config.js` 的顶层 `version=227`、`season=400001` 格式不同于 `card.js`，属于独立配置版本号，不要求与卡片补丁号相等。
- [官方玩法公告](https://www.taptap.cn/moment/858762475896573628)介绍时间卡片与英雄联盟传奇模式，公告注明 10 月 15 日至 11 月 3 日测试、11 月 4 日正式上线。页面统一标注“先遣服（数据以实际上线为准）”；源快照版本保留在数据文件中用于维护。
- 卡图链接来自 `https://game.gtimg.cn/images/lol/act/jkzlk/mode16s400001/tomato/`；导入保留 `sIcon` 原链接并使用本地已下载图。
- 参考截图用于卡框设计，不用于覆盖数据。例如截图中的“德玛西亚巨像 3-3”与当前快照的 `3-5` 不同；页面保留快照值。

## 字段解释

| 字段 | 含义与使用方式 |
| --- | --- |
| `version` | 源资料版本字符串，保留在数据文件用于追溯；页面标注先遣服，不推导上线日期。 |
| `season` | 官方模式／客户端标识 `S400001`，不是站内 `season_id`。 |
| `setId` | 源资料的 set 标识 `16`，不据此修改站内赛季登记。 |
| `time` | 快照提供的更新时间；不能当作本次下载时间。 |
| `data` | 按卡片 ID 索引的对象，当前 201 条。 |
| `id` | 卡片唯一标识，匹配本地文件名的 ID 前缀。 |
| `iRarityTier` | 卡片星级，字符串 `1` 至 `5`；分类以此为准，不使用名称中的罗马数字或 ID 前缀推断。 |
| `sName` | 卡片名称，保留原文。 |
| `sIcon` | 官方图片 URL；图片编号不保证等于卡片 ID，例如 `7210024` 使用 URL `7210025.png`。 |
| `sTags` | `范围标记\|分类编号`。首段出现 `0` 和 `400001`，从内容推测为通用／模式专属，未找到正式枚举说明，不对玩家做强断言。 |
| `sArgs` | 以 `^` 分隔的 `键=值` 参数；仅按第一个 `=` 切分，保留大小写和值里的 `\|`。 |
| `sDesc` | 已填入数值的完整效果文案，直接展示，不用参数重新拼写或补充未经确认的效果。 |
| `assets` | 导入器新增的本地图像清单：文件路径、原始宽高、SHA-256、显示类型；缺图为 null。 |
| `asset_failures` | 导入器新增：本次下载失败的卡片 ID、官方 URL、错误与检查时间。 |
| `provenance` | 导入器新增：采集时间、`card.js` 地址、ETag、Last-Modified 和归档目录名。 |

分类第二段的浏览映射是：`1001` 经济、`1002` 弈子、`1003` 装备、`1004` 强化、`1005` 纹章、`1006` 特殊。
这是基于源档案和卡片内容的归纳，不是已核实的官方标签字典。个别归类不符合直觉，例如“熔铸之神的馈赠”属于 `1002`，仍保留源分类。

## 参数解释与边界

`round` 是卡片效果的生效回合，不是抽取／获得卡片的回合；`round2` 是后续效果回合。
条件效果仍需满足描述中的条件，例如“铁匠铺 III”在 `1-2` 生效，但达到 5 级才获得装备。
同时搜索主回合和后续回合；详情始终先列 `round` 再列 `round2`，不依赖 JSON 参数顺序。

下表覆盖当前快照的全部参数名。除回合以外，语义由相应卡片描述推断；没有官方字段字典时，不把它们解释为独立的已验证规则。

| 参数 | 从本快照可确认／推断的用途 |
| --- | --- |
| `round`, `round2` | 首次生效／后续生效回合。 |
| `gold`, `gold2` | 金币相关数值，`gold2` 在补助金中表示后续每回合金币。 |
| `xp`, `interest` | 经验值、利息上限。 |
| `count`, `flatCount`, `extraCount` | 数量、固定数量、额外数量；具体物品与触发范围看原文。 |
| `num`, `num1`, `num2`, `num3`, `num4` | 多用途数字槽位，如候选数、购买次数、累计门槛等，不能统一理解为弈子数。 |
| `itemCount`, `itemCount1`, `itemCount2` | 各项奖励数量；字段名虽带 item，也用于奖励弈子的描述。 |
| `cost`, `cost1`, `cost2`, `cost3`, `unlockCost` | 费用／费用门槛／解锁费用。 |
| `star`, `star1`, `copyStar`, `sellStar` | 星级或其他等级数值；`穿梭未来` 的 `star=8` 实际对应玩家升至 8 级。`sellStar` 的具体引擎语义未确认，原样保留。 |
| `cardStar` | 时间卡片星级相关值，可能是变换后的星级或展示伪装，不是当前卡片星级。 |
| `level`, `times`, `plus`, `plusRound` | 等级、次数、增量、回合／进度增量，需结合卡片描述。 |
| `equipnum`, `equipNum` | 装备数量类参数；大小写不同，原样保留，不合并。 |
| `detail` | 详情引用编号列表（如 `20037\|20038`）；源文件没有被引用对象，不能凭编号生成额外效果。 |
| `pct`, `pct1`, `pct2` | 百分比数值槽，作用对象和增幅／减免由描述确定。 |
| `hp`, `maxhp`, `hpFlat`, `hpPerm`, `legendhp` | 生命值、最大生命、固定生命、永久生命或小小英雄生命相关数值；对象依描述。 |
| `hpThreshold`, `perHpThresh`, `maxStack` | 生命门槛、每档门槛、最大层数。 |
| `hplip`, `hppct` | 治安官之盾的生命阈值／护盾比例参数；命名不规范，保留原文，不扩展成通用规则。 |
| `silverCoin`, `soul`, `sunShard` | 银蛇币、暗影灵魂、太阳碎片数量。 |
| `sec`, `sec1`, `timedelay` | 秒数／延迟参数；未在描述明确的值不自行显示为额外规则。 |
| `range`, `manaRecover`, `manaRecoverLow` | 攻击距离及法力回复相关参数；条件以原文为准。 |
| `heronum`, `indepCount`, `slots` | 弈子数量、独立单位数量、占用栏位。 |
| `choiceFrom`, `choiceTo` | 候选数量和可选择数量，例如 4 选 1。 |
| `classNum`, `traitTier`, `traitTier1` | 羁绊／职业数量或羁绊层级。 |
| `tier1`, `tier2`, `tier3` | 多档层级值，需配合详情资料理解，不据此编造层级收益。 |

## 图片与设计

1 星 20 张、2 星 30 张、3 星 60 张、4 星 50 张、5 星 41 张。190 张 PNG 保留原文件像素：

| 原始尺寸 | 数量 | 显示策略 |
| --- | --- | --- |
| 326×430 | 104 | 等比放大展示，CSS 内缩裁切去掉自带边缘，不修改原始图片。 |
| 326×524 | 59 | 长幅图等比 cover、轻度放大，新金属包边覆盖旧边缘。 |
| 324×526 | 27 | 与上一类共用布局，不因 2px 裁切差异改变卡框位置。 |

统一纵向六边形外轮廓与星点。五档边框分别采用银钢刻线、翡翠叶饰、冰蓝晶角、紫晶菱扣、棱彩金边与五角冠饰，形状、金属材质、侧扣和底部印记均有区别。SVG 渐变在页面定义一次，卡框和详情克隆共用，不产生重复 ID。浅／深主题复用站点偏好。
标题和描述优先下移，扩大插画露出面积；前端按实际文字高度与屏宽计算安全位置，长文案自动上移，渐变遮罩随文字位置移动。筛选、详情打开、字体加载和窗口缩放后重新适配。原始图的包边遮挡保持不变。详情只保留卡面、回合和完整效果，不提供复制链接按钮。
顶部徽记采用金橘、双叶与时空轨道的矢量设计。卡片外不再重复类型和回合；页脚只保留站点标识与返回导航。
色彩设计为银灰、绿、蓝、紫、橙金；3／4／5 星对应参考图的蓝／紫／橙方向，2 星绿色是本工具的区分设计，非官方色值认证。
11 张卡的 `sIcon` 在 2026-10-29 采集时返回 404，保留文字与“卡图暂缺”占位，不用其他卡图冒充：`7250012` 一直缺图；`7230114`、`7240092`–`7240097` 旧快照共用 `7220015.png`，`7250071` 旧快照使用 `7250010.png`，`7210027` 旧快照使用现归 `7210028` 的 `7210028.png`，官方改为专属地址后尚未上传；`7220040` 改名后指向新地址 `7220139.png`。旧地址仍可访问并不代表可沿用，未经同卡确认不回填。

## 更新

采集写入新的归档目录（例如被忽略的 `instance/orange-fortune-archive/<北京时间>/`），默认与当前 `cards.json` 和本地图片比较，并把对比基准复制进归档：

```powershell
python -I scripts/collect_orange_fortune.py --output instance/orange-fortune-archive/<时间戳>
python -I scripts/collect_orange_fortune.py --output <同一目录> --retry-images   # 仅重试超时/网络错误
python scripts/import_orange_fortune.py --source <同一目录>
python -m pytest -q
node --check static/orange-fortune.js
```

归档包含版本目录与每个接口的原始响应和解析 JSON、`selection.json`（分支依据）、`cards/normalized.json`（原始字段、有序参数、`energy=null`）、图片与 `images/failures.json`、`manifest.json`（来源、HTTP 状态、ETag/Last-Modified、大小、SHA-256）、按 ID 逐字段的 `diff.json` 和中文 `report.md`。下载内容只解析为 JSON 或图片，不执行；404 不重试，超时与 5xx 有限重试；非法 JSON 保留原始响应并中止。

导入器只接受归档中下载成功、URL 与当前 `sIcon` 一致且哈希匹配的图片，复制为卡片 ID 命名的文件，删除已失效的旧图并生成 `static/tools/orange-fortune/cards.json`。不修改归档。
提交新资料与图片，重启 Web 以刷新进程内只读缓存。图片与 CSS/JS 使用 `static_v()`。
新增行为的入口在 `orange_fortune_service.py`、`templates/orange_fortune.html` 和同名静态文件；无 JS 时服务端表单仍支持筛选并展示完整效果。
