# 玩法资料接入

赛季玩法与上游文件名分开：`galaxy.js` 不一定叫“星系”，`adventure.js` 也不一定叫“仙灵”。
在源档案核对当前赛季官方说明，用稳定 ID 关联记录，以 `display_name` 定义用户看到的名称。
同名事件不应合并，除非官方明确表示它们是同一事件的变体。

源档案 `mechanics/index.json` 为每组玩法声明 `id`、`kind`、`display_name`、`file`，
并可提供 `presentation` 和 `description`。Web 导入器将这些元数据保留到资料包。
`kind` 表示玩法语义，不要求前端增加同名分支。未知 kind 默认采用 `cards.v1`；
显式指定但不支持的模板会报错，不丢弃字段或静默降级。

支持的资料模板为卡片 `cards.v1`、变体 `variants.v1`、阶段 `stages.v1`、
表格 `table.v1`。历史仙灵、神明等保留 `legacy.v1`。新资料可携带分类、标签、条件和
阶段/变体信息，页面根据资料生成页签、搜索及分类筛选。玩法简介为纯文本，服务端转义后展示。

含简介的包声明 `reference.overview.v1`；旧服务会要求先更新代码，新服务继续接收旧包。
打包、上传校验和页面展示共用模板约定。正文与紧凑 index 必须一致，玩法元数据变化也计入差异报告。

扩展顺序：修正外部档案及来源 → 独立目录生成 → 离线打包校验 → 后台预览 → 发布。
普通新玩法资料不需要数据库迁移或再次部署。新增展示模板、交互或模拟器规则时，必须先实现并
测试相应能力，再让包声明该能力；不接受包内任意脚本。

## 画之灵返场的边界

18.11.1 的 `galaxy.js` 为奇遇资料，其中包含狂风奇遇；`equip.js` 中 EffectType=71 的
记录是绘境格，应提取为“绘境”玩法，排除出可携带装备池。命名和绘境规则参照
[官方奇遇说明](https://www.taptap.cn/moment/852521787559247892)与
[官方绘境说明](https://www.taptap.cn/moment/851886704909353222)。

这些玩法页签用于规则查阅，不自动模拟奇遇造成的装备槽/人口变化，也不把绘境格冒充弈子。
新增棋盘格放置、战斗效果或分享码字段需要独立设计和能力声明，不能仅靠名称触发行为。

## 可重复的强化符文导入

如源档案包含 `source-snapshots/hex.json`，导入器优先读取并核对补丁和官方客户端代号。
可用 `augment-image-overrides.json` 保存逐条图片修复来源；版本、名称、原始 URL 与本地路径
都须匹配。官方旧图复用须标明未核验当前美术，缺图占位不得伪装成官方图。
