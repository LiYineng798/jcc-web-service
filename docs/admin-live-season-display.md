# 实时阵容赛季管理优化

本改动继续在 `codex/admin-season-hub` worktree 实现，等待统一验收后合并 main。复用资料库/模拟器的赛季列表组件和视觉样式，保留「实时阵容 → 赛季管理」的独立入口。

## 操作行为

- 展示区只排列启用、归档赛季，序号连续为 1..N；普通阵容的筛选、创建和批量导入共用这些分类及顺序。
- 隐藏、停用赛季收进默认折叠的「未展示赛季」，保留名称、ID、说明和状态，不提供序号、排序或设默认操作。重新展示（启用或归档）追加到末尾。
- 当前默认赛季显示标记，其余公开赛季可设为默认。当前默认被隐藏/停用后自动回退到第一项；全部关闭时默认为空，首次恢复自动成为默认。
- 桌面使用单栏紧凑行，信息在左、状态与操作在右；窄屏分行，手机触点至少 44px；支持深浅色、键盘和折叠状态保留。
- 保留新增、刷新功能。新增默认隐藏，成功后自动展开收纳区显示新条目；这仍只创建阵容分类，不创建资料库/模拟器资料。
- 状态/排序/默认保存、新增都采用接口返回的赛季名单，成功后不依赖额外刷新请求；同步失效普通阵容选项缓存。失败保持原状态，重复提交受阻。

## 配置与兼容

运行时依旧使用 `instance/live-comps-seasons.json`。读取旧名单时保留公开条目相对顺序、压紧序号，将非公开条目 order 归一为 null；只读不会落盘，下次写操作持久化。原 API 路径不变；对隐藏/停用项提交排序、将非公开项设为默认、无效状态或排序值返回 400。

新默认赛季没有自己的阵容 JSON 时显示空列表。旧逻辑会退回默认数据路径，可能把原 S17 数据当作其他赛季展示；现在只有原 S17 分类继续使用其约定的旧路径，其他分类读取自己的文件。切换默认或展示状态不会移动、删除、重写阵容数据和人工补码文件。

资料赛季与阵容分类仍独立，不改 PostgreSQL 表结构、不需要 migration 或新增环境变量。
