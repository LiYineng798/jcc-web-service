# 统一操作通知

## 范围与设计

用户提供的 notifications-5 React 卡片作为视觉参考。现有 Flask/Jinja + 原生 JavaScript 架构继续使用，组件在 static/notifications.js、样式在 static/notifications.css，通过 seo_head.html 在页面业务脚本前加载，包含不使用站点 CSS 的模拟器。不引入 React、Tailwind、shadcn、图标包或外部图片；图标使用固定内联 SVG，消息通过 textContent 写入。

桌面右上方、手机顶部安全区显示独立卡片，图标/标题/说明/关闭按钮保持一致。四种类型为 success、info、warning、error；深浅主题都有独立前景色。手机避开底部导航，visualViewport 跟随可视区域；小屏最大高度内可以滚动。原生 dialog 打开时通知容器加入该 dialog，并用 manual popover 进入顶层；关闭 dialog 后移回 body。没有 Popover API 时使用固定定位层。

## 提示入口清单

| 页面/模块 | 改造内容 |
|---|---|
| 登录、注册、找回密码、退出登录 | 错误/验证码发送/重置结果/成功提示改用通知卡片；登录和注册跳转后保留一次成功反馈（sessionStorage，10 秒失效，不含凭据） |
| 首页普通阵容与实时阵容 | 复制成功/失败、缺少阵容码、点赞/收藏/取消收藏、隐藏、失效反馈、保存后返回、登录后继续操作 |
| 作者页 | 复制、点赞、收藏、失效反馈及操作失败 |
| 个人中心 | 最近浏览/最近复制的复制按钮每次反馈；取消复制后禁用 1.4 秒；头像保存成功/失败 |
| 阵容新增/编辑 | 未登录、解析错误、未选赛季、提交异常 |
| 管理员后台 | 原顶部 setNotice 涵盖阵容、反馈、赛季显示、实时阵容上传/补码/导入、公告、系统设置、留言、用户密码/禁用等；通用按钮错误和非确认型 alert 全部接入 |
| 后台表单 | 密码校验/网络错误、新建赛季、补码失败弹出错误卡片；保留弹窗内错误说明 |
| 模拟器 | 人口/装备/上阵/符文限制、导入结果、阵容码导出、分享链接复制、图片与海报结果 |
| 公共留言/失效反馈表单 | 必填及提交失败同时显示通知和字段附近信息，原输入内容保留 |

静态说明、登录身份文字、加载失败空状态、上传任务进度和确认弹窗不属于短暂操作通知，继续保留。普通阵容详情及实时详情当前没有复制入口，未虚构新业务。

## 生命周期与性能

- 每次复制成功立刻新增一个独立通知，不按内容去重，统计请求不阻塞成功反馈。
- 同时最多桌面 4 张、手机 3 张，超限移除最旧卡片；高频点击仍会为每次反馈创建新身份。
- 通常 3.8 秒自动移除，错误 6.5 秒；悬停/键盘焦点停留时暂停，手动关闭或淘汰均清理计时器。
- 消息为空不创建节点；最后一条消失后移除容器及 visualViewport 监听。
- 动画只使用 opacity/transform，支持 prefers-reduced-motion；无全局 DOM 观察器、轮询或新增通知 API。
- 复制后的首页/作者列表刷新以 500ms 合并；复制统计保留每次请求，统计失败不误报剪贴板失败。
- 后台保留数据更新后的必要渲染，取消提示超时导致的第二次整页渲染。
- 浏览器拒绝复制时显示失败，兼容旧 execCommand 的返回值并在 finally 清理临时 textarea。

无数据库迁移、依赖、环境变量或生产更新。本分支待用户确认后合并。
